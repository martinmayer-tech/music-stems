# Changelog (0000010-http-api, 16 Nov 2026)

**Feature:** Add the HTTP API
**Version:** set by the merge queue at merge
**PR:** 9

## What changed

- Added `stem_service/api.py` with `create_app()` and four routes: `POST /jobs`, `GET /jobs`, `GET /jobs/{id}`, and `GET /jobs/{id}/stems/{name}`.
- Added upload checks for the extension (WAV, FLAC, MP3, and M4A) and the size (`STEMS_MAX_UPLOAD_MB`, default 500).
- Added `python -m stem_service`, which serves the app with uvicorn on `127.0.0.1` by default.
- Added the host, port, upload limit, and `uploads` folder settings to `stem_service/config.py`.
- Added the `service` extra (`fastapi`, `uvicorn`, `python-multipart`) and `httpx` in the `dev` extra of `pyproject.toml`, and the CI install of the `service` extra.
- Added ADR 0005, the OpenAPI spec, and updated the `stem-service` docs and the living docs.

## Why

No process outside Python could submit a job or fetch stems. The web page in step 6 needs an API to call.

## Deviations

- The CI install line and `src/stem-core/tests/test_pin_ci.py` changed from `.[dev,separation]` to `.[dev,service,separation]`, so CI installs the API libraries.

## Validation results

- `ruff check .` exits 0. `pytest` gives 102 passed and 1 deselected. The full pack suite gives 0 new failures and 59 inherited failures.
- A live uvicorn run took an upload, ran the job to `done`, and served 5 stems as `audio/wav`. A `.txt` upload, an oversized upload, an unknown job, and an unknown stem returned 415, 413, 404, and 404.
- `pip-audit` reports no known vulnerabilities.
